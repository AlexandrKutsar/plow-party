# Art

All visual content of the game, and nothing else: models, textures, materials, shaders, animations, VFX, UI graphics, and the visual prefabs built from them. Code, gameplay prefabs, and scenes live elsewhere. Decisions: ADR-0008 (layout and rules), ADR-0009 (models generated by Blender scripts, one palette).

## Layout

```
Art/
  Shared/                 used by many assets: T_Palette.png, M_Palette.mat, shaders
  Vehicles/<Asset>/       Vehicle/  → SM_Vehicle.fbx, V_Vehicle.prefab
  Critters/<Asset>/       planned
  Environment/<Asset>/    planned: ground, buildings, Drifts, Drop-Off Zone
  Props/<Asset>/          planned: Loot, Gadget pickups, snowballs
  VFX/<Effect>/           planned: particle prefabs and their textures
  UI/                     planned: sprites, icons, fonts (imported as sprites)
```

Group by what the content is, not by which feature uses it: a Critter appears in the Match and on menu screens. Every asset gets its own folder holding all its files. Audio is not art; it goes to `_Project/Audio/` when it arrives.

## Naming

Asset names are PascalCase after a type prefix; the name after the prefix is the `GLOSSARY.md` term.

| Prefix | Type | Example |
|---|---|---|
| `SM_` | static or rigid model (FBX) | `SM_Vehicle.fbx` |
| `SK_` | skinned model with a rig (FBX) | `SK_Critter_Fox.fbx` |
| `T_` | texture | `T_Palette.png` |
| `M_` | material | `M_Palette.mat` |
| `SG_` | Shader Graph | `SG_SnowSurface.shadergraph` |
| `A_` | animation clip | `A_Critter_Cheer.anim` |
| `AC_` | animator controller | `AC_Critter.controller` |
| `V_` | visual prefab | `V_Vehicle.prefab` |
| `FX_` | VFX prefab | `FX_RamImpact.prefab` |
| `UI_` | UI sprite or atlas | `UI_GadgetButton.png` |

Variants append `_<Variant>`: `SK_Critter_Fox`, `T_Snow_Normal`.

## Two kinds of prefab

- **Visual prefab** `V_<Asset>` lives here, next to its model. It holds only Unity components: meshes, renderers, animators, particle systems, and named anchor transforms (`CritterSeat`, `Bucket`). No project scripts, no colliders, no `NetworkObject`.
- **Gameplay prefab** lives in its feature's `Prefabs/` folder (for example `Gameplay/Vehicle/Prefabs/Vehicle.prefab`). It carries the scripts and networking and nests the visual prefab as a child named `Model`.

So the look of anything can be replaced by editing or swapping its `V_` prefab, without touching gameplay or networking. Simulation never reads mesh geometry; sizes come from config.

## Import rules

`Editor/ArtImport/ArtImportPostprocessor` enforces these on every import under `Art/`; change the rule there, not per asset in the Inspector.

- Models: scale 1, no cameras, lights, blend shapes, or visibility; not readable. `SK_` models import a Generic rig and their animations; `SM_` models import none. A source material named `Palette` is remapped to `Shared/M_Palette.mat`.
- Textures: max 1024 (UI 2048), mipmaps on for world textures and off for UI, Android ASTC 6×6. `T_Palette.png` is the exception: point filter, clamp, uncompressed, no mipmaps, so palette cells never bleed.

## Materials and budgets

- One URP material for all models: `M_Palette.mat` (Simple Lit, palette as base map). Faces pick colors by UV. A new color goes into the palette; a new material needs a reason recorded in ADR-0009 or a new ADR (transparency, a snow shader, UI).
- Per-Participant colors use a material property block or a palette swap, never a material copy.
- A Vehicle or Critter stays under ~1500 triangles; a texture other than the palette needs a reason.

## Sources and generated files

- Editable sources (Blender scripts, `.blend`, `.psd`, `.kra`) live outside `client/`, under `art/` at the repo root (see `art/CLAUDE.md`). `client/` only receives exports.
- Generated outputs (`SM_Vehicle.fbx`, `T_Palette.png`) are rebuilt from `art/blender/`; a hand edit in Unity or Blender is lost on the next build.
- Binary formats are committed through Git LFS (`.gitattributes`).

## Adding an asset

1. Create `Art/<Category>/<Asset>/` and put the exported files there with their prefixes.
2. Build `V_<Asset>.prefab` from the model: anchors named after glossary terms, no scripts.
3. Nest it as `Model` in the feature's gameplay prefab.
4. Add a row to the table below.
